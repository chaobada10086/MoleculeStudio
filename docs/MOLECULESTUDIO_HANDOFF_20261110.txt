三、用户目标与已经确认的界面约定
================================

用户要的是教科书式机理箭头：实心尖三角、端点精准、曲线自然、支持多个弯。
手绘和 AI 绘图都应快捷，用户允许重写箭头模块，也允许子代理并要求主代理验收。
不要恢复一堆按大/中/小重复排列的冗杂箭头菜单。

“图形”页：
  机理箭头：独立一栏，只放一个新自动机理箭头工具。
  机理推演：生成下一步、通用碱 B⁻、亲核 Nu⁻。
  其他箭头按反应、平衡/共振、更多样式整理；旧弧线仍可读。

正常用法：
  选择机理箭头，从电子来源拖到目标；来源/目标可以是原子或键。
  框选同一步的结构和机理箭头，点击“生成下一步”。
  下一步是右侧可编辑结构，原反应物保留，支持一次撤销。
  仅选择机理箭头工具，不会重置选中的旧机理箭头路线。

本轮新增：
  选中骨架碳，按主键盘 +（Shift+=）或 -，无需鼠标继续悬停在该原子。
  中性碳切到正/负一价或单自由基时，减少一个隐含氢。
  恢复中性/取消自由基时相应恢复隐含氢；显式画出的 H/D 不会自动删除。
  B/Nu 是显式通用角色，不能把元素硼 B 全局替换成“碱”。
  点通用试剂按钮可插入；选中孤立原子可转换；准确的 B/Nu 文字及旁边负号也可转换。
  用户真实图里的 B 和负号恰好是两个文字对象，这个转换路径已验证。

B. 从电子箭头生成下一步

studio\engine\mechanism_step.hpp
  namespace r62::mechanism
  struct ElectronMove { ObjectRef source, target; };
  Error generateNextStep(Document&, const vector<ElectronMove>&, vector<ObjectRef>* created);
  底层会修改传入文档，调用者应提供事务或隔离副本。

实现逻辑：
  收集反应中心和参与的完整连通结构；
  所有电子移动同步累加键级变化和形式电荷变化；
  逐原子保持氢数，不通过偷偷补氢掩盖缺失的机理箭头；
  键来源进攻另一原子时枚举两端，必须得到唯一合理的最终结构；
  验证键级、价态、电荷守恒，再生成结构。
  支持 atom→atom、atom→相邻bond、bond→atom、相邻bond→bond。
  分子间新成键使用刚体转动/平移搜索，避免捏坏现有环和构型。
  最终重新按“产物键图”分连通分量，把独立的 BH、离去离子等分开放置。
  主产物优先，分量只整体平移；间距考虑标签、电荷和隐含氢。

studio\engine\mechanism_infer.hpp
  Error inferElectronMoves(const Document&, const vector<ArrowParams>&, vector<ElectronMove>*);
  对没有绑定的箭头，从附近原子及整段键寻找候选。
  用本地键长确定正常留白范围，方向只影响候选顺序。
  联合运行化学规则，只有唯一化学结果才接受；不会截断候选后假称唯一。
  已有明确绑定优先；失效/远离的绑定拒绝，不自动改指别处。
  带标签原子裁剪后可以离原子中心较远：
    明确绑定的端点可位于标签框边界窄带；
    未绑定候选不会因此被任意放宽。
  通用 B/Nu 文字较宽，角色端点允许专门的正常留白。

D. B / Nu 通用角色

存储：
  扩展键 pst.attr.MoleculeStudioRole，值 base / nucleophile。
  NodeType::Query + 标签 B / Nu。
  核心存储不允许 element=0，因此底层 element=6 是占位值。
  化学意义必须看 Query+role，绝不能把它当真正的碳或硼算组成。

  base 只允许与 H 形成该单键；Nu 用于一般亲核单键形成。
  通用中性碱的任意酸碱化学、一般 B/Nu 反应库不在本轮实现范围。

六、踩过的坑及后续边界
======================

1. Windows 头文件定义 near 宏。C++ 变量不要命名 near！
   本轮已用 boundIsNear / nearbyLengths，单独头文件语法通过不代表 Windows 主程序能编译。

2. core::Box 默认 min=max=(0,0)，add() 不会自动识别空哨兵。
   为分量累积包围盒必须以真实首点初始化：
     Box box(positions.at(part.front()), positions.at(part.front()));
   不可用默认 Box，也不可用 (1,1),(-1,-1) 再 add() 以为能消除原点。
   这会把 BH 等副产物排到很远处；当前已修，并验证不同页面位置得到相同净间距。

3. 最终原子文字由 appendRich 转为 Polygon 字形轮廓，primitive.text 可能为空。
   “有没有负号”的测试应查正确原子来源的实际字形/截图，不能只查文本字段。

4. 先记录语义端点，再裁剪可见路线。
   字母/隐H的避让会改变 begin/end；已有绑定需要检查标签边界，不能只用原子中心距离。
   反过来也不能为解决留白问题，无限制放宽所有未绑定端点。

5. 两个 GenericNickname 空标签碳曾导致旧用户羟醛图被拒绝。
   core step 有窄范围兼容归一化，电子状态编辑也会处理无隐藏内容的空 Query 碳。
   不要把有真实缩写/查询负载的节点全部擅自变成元素碳。

6. 真实用户丙二酸酯图的 B⁻ 原本是两个 Text，而非硼原子。
   native 原图内该轮新增 alias atom23/26、中心碳24、显式H25，箭头4/5。
   这些仅是该固定测试夹具的内部 ID，导出、粘贴、新文档可能全部重映射。
   不要把测试 ID 当通用业务常量。

7. 旧版本样例/文档说明可能落后。
   docs\MECHANISM_NEXT_STEP.md 曾写“缩写需先展开”，v8 已增加相关已知缩写的副本展开。
   docs\MECHANISM_ROUTING.md 部分标注 v3，理解历史设计可以读；当前行为以源码和本交接为准。

8. 仍存在的明确边界，不要对用户过度承诺：
   - 机理生成是有限的双电子规则与唯一性验证，不是任意有机反应预测器。
   - 能画 fishhook 不等于能生成自由基机理下一步。
   - 反应中心芳香/特殊价态/不确定立体化学、复杂环化等会拒绝。
   - 通用 B/Nu 当前主要覆盖负离子供体形成一个单键。
   - 任意缩写/图片/纯文字结构不会凭空变成可靠化学图。
   - 移动分子本身不会自动重画已存在的机理箭头；目前检查失效绑定。
   - 标签避让使用估计边界；本轮对实际字形和典型短箭头验收，不是任意字体/字号全证明。
   - 寻路为有界启发式，不保证全局最优。
   - CDXML 多弯路线是 MoleculeStudio 扩展，外部软件可能只显示圆弧回退。
   - 修改后的中间控制点不是完整多段 Bezier 编辑器。
   - 新默认外观不批量覆盖用户所有既有手动路线；演示副本的短箭头单独重规划过。
