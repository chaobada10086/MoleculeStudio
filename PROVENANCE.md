# Provenance and clean-room status

This file records what is original to MoleculeStudio and what still needs
attention before the project can be described as a fully clean-room,
Apache-2.0 release. It is intentionally explicit: an open-source claim is only
as good as its provenance record.

## Replaced for this release

The nickname library that used to be extracted from an installed ChemDraw
(`chemdraw_catalog.hpp`, `chemdraw_alias_catalog.hpp`,
`chemdraw_nicknames.json`, `import_chemdraw_catalog.py`) has been removed.

It is replaced by:
- `re_round62_viewer/studio/nicknames.src.json` - 317 authored
  `name -> SMILES` entries (attachment point written as `[*]`);
- `re_round62_viewer/studio/tools/build_nickname_catalog.py` - RDKit layout
  that generates `nickname_catalog.hpp` (compiled into the editor) and
  `nicknames.json` (Python backend);
- `re_round62_viewer/studio/tools/nicknames_skipped.json` - names that were
  deliberately not guessed, with the reason (mostly nucleotide/sugar residues
  whose attachment point is ambiguous, and obscure vendor-specific acronyms).

No vendor fragment coordinates, node ids or structures were copied; the
structures were authored from chemistry knowledge and validated with RDKit
(formula, valence, one attachment point, CIP where defined).

Name-list note: the 309 abbreviation strings that survive into the generated
catalog are the same strings that also appeared in the old vendor name list.
Names/short labels are functional identifiers, not creative expression; only
the abbreviation strings are shared. Every structure and every coordinate in
the shipped catalog is generated by our script from the authored SMILES table.
The earlier wording "317 hand-authored entries" describes the SMILES table, not
the provenance of the name strings.

The hotspot key map lives in `studio/keymap_data.hpp` (namespace `keymap`)
and is loaded by `studio/shortcut_catalog.hpp`. It is functional data - which
key performs which command - transcribed/re-authored from the ChemDraw 26
default shortcut tables and public documentation. No vendor resource file is
read at build or run time. The table keeps vendor command identifiers (for
example `chooseRingTool_Benzene`) because they are the interoperability names
used by CDXML and the clipboard; they are not vendor code or artwork.

## Removed on 2026-10-28

The items previously listed here as open work are now resolved:

1. **ChemDraw-exported test fixtures.** `studio/fixtures/stereo_reference/`
   (six CDXML/SVG pairs), `native_arrow_reference.cdxml`,
   `native_boc_attached.cdxml`, `native_boc_label.cdxml` and
   `retro_native_saved.cdxml` were deleted. The checks that consumed them
   (the native-contour export in `stereo_render_tests.hpp`, the native arrow
   case in `interaction_tests.hpp`, `verify_stereo_geometry.py`) were removed
   with them; the remaining stereo assertions are self-contained.
2. **Toolbar inventory.** `host_integration/drawing_inventory/tools.csv` was
   removed from the tree. The T19 integration build script now keeps the
   already-generated `next/integration/source_tools.hpp` when the inventory is
   absent instead of requiring it.
3. **ChemDraw-dependent verification scripts.**
   `verify_native_catalog.ps1`, `carbonyl_reference.ps1`,
   `oxygen_layout_reference.ps1` and `verify_carbonyl_geometry.py` were
   deleted; they constructed a ChemDraw ActiveX object and are not part of the
   shipped tooling.
4. **Dead ActiveX code.** The `#if 0` ChemDraw control block and its
   `invoke()` helper in `studio/chem_service.hpp` were removed, together with
   the `ChemDrawControl_x64.ChemDrawCtl` ProgID and CLSID usage. No COM or
   ActiveX path remains in the source or the binary.
5. **Documentation.** The 2026-10-17 section of `studio/README.md` is marked
   historical, with a note describing the local RDKit/OPSIN/NISPO backends that
   replaced the ChemDraw services; the current dependency statements no longer
   require a ChemDraw installation. `out/Studio/chemdraw_nicknames.json` was
   deleted.

The bond-geometry rewrite of 2026-10-28 (see `CLEANROOM.md`) is unchanged and
still stands.

## Still to do before a clean-room claim

1. **Bond rendering code.** `engine/bonds_geometry.cpp` and the `clip()`
   routine were restated from published drawing conventions and no longer cite
   decompiled vendor code, but the rewrite was done in the same repository by
   an engineer who had seen the previous file. A strict independent clean-room
   pass is still advisable before a formal legal review (see `CLEANROOM.md`).
2. **Bundled third-party runtimes** (JDK, LibreOffice kit, Node, Python, PyTorch,
   RDKit, PDFium, FFmpeg, libvips) stay under their own licenses; see
   `THIRD_PARTY_NOTICES.md` and `licenses/`. DeepSeek Harness (`dsh_core`) is
   vendored - confirm its upstream license terms before publishing a binary.
3. **ChemDraw brand references** in UI text and code comments: keep only
   nominative, descriptive mentions ("CDXML is a ChemDraw file format") and the
   non-affiliation notice in `TRADEMARKS.md`.
4. **Historical T19 records.** `out/T19/.../README.md`, `RESULTS.md` and
   `pre_run_manifest.json` still mention the removed fixtures and inventory as
   development history. They are records, not build inputs; prune them if the
   public tree should not carry those references at all.

## Files intentionally not in the source release

- `out/Studio/` build output (executables, objects, logs, manifests);
- `*.before-*` pre-fix snapshots and local backups;
- `__pycache__`, `*.pyc`, local settings and machine-specific paths;
- the stale `SOURCE_SHA256.json` / `verify_package.py` pair (hashes were
  regenerated for every internal patch; regenerate them for a tagged release).


## Implementation cleanup — 2026-10-30 (supersedes the older status above)

The current bond primitive generator was newly implemented as a Builder over
the project geometry interface, and label clearance was newly implemented using
closed-polygon/half-plane intersections. No external editor is invoked.
The historical caveat is retained: this work occurred in the same repository;
it is not a certification by an independent clean-room team.

The unlinked next/host COM implementation has been removed from the product
source tree. Obsolete automation test inputs were replaced with a generated
project benzene fixture. Shortcut functions and routes use project names;
shortcut_legacy.hpp reads old persisted IDs solely for configuration migration.
The nonfunctional ChemScript placeholder was removed.

The portable runtime now uses the official RDKit 2024.9.6 Windows wheel, SHA-256
recorded with the release verification. This wheel contains no RDKitChemDraw,
RDChemDrawLib, RDChemDrawReactionLib or rdChemDraw binary extension. Two unused
RDKit COM automation utilities were omitted. RDKit's independently developed
open-source reader is used through project-authored temporary-CDXML adaptation;
its implementation remains an attributed third-party dependency.

Required clipboard/OLE protocol labels and public CDX/CDXML property identifiers
remain literal interoperability names. Historical keyboard command labels,
BioDraw identifiers and journal-style numeric defaults have not been disguised
as newly invented data. They describe operations and geometry, not calls to a
vendor engine. Their previously recorded origins remain applicable.


## License and source inventory update — 2026-10-30

The previous 39 license-text placeholders have been resolved from bundled
files, original source headers, reviewed upstream licenses, or explicitly
recorded parent-package inheritance. Twenty-seven embedded sharp/libvips
components were added. Full component notices remain in licenses/.

SOURCES.txt and SOURCE_AVAILABILITY.json replace the old source-offer template.
The companion third-party source distribution includes exact source archives, the LibreOffice kit
modifications and build scripts, JDK source/build revisions, FFmpeg sources and
recipe, sharp/libvips dependency sources and patches, JNA InChI/InChI source,
and exact bundled tqdm source snapshots. The source-only editor ZIP carries
the manifest and points to the companion source archive.

This resolves license-material/source-availability preparation. It does not
erase the historical provenance record or certify independent clean-room work.
